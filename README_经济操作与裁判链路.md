# POLAR-RM 经济操作与裁判链路

本文说明独立经济工作区的比赛规则、机器人权限、裁判系统命令与 Mock 边界。实现依据本地 2026 规则手册与《RoboMaster 2026 机甲大师高校系列赛通信协议 V1.3.1（20260519）》；正式比赛以现场下发状态为最终结果。

## 1. 打开与交互

- `B`：打开/关闭完整经济工作区。
- `ProjectileShop` 的绑定键：直接打开“弹丸”页。
- 鼠标滚轮或方向键：切换分类与商品；`Enter` 确认当前操作；`Esc` 取消待确认操作或关闭面板。
- 补给区普通弹丸采用二次点击/二次 `Enter` 确认。
- 远程弹丸、远程补血、金币复活和空中支援必须长按确认 600ms。

工作区顶部显示比赛模式、机器人和 `MOCK / REFEREE` 链路；左栏显示当前金币、累计金币、待扣金额、弹量与血量；中间为商品列表；右侧为条件、确认按钮和最近交易。720p/900p 使用双栏布局，1080p 及以上在空间允许时使用三栏布局。

## 4. CommonCommand 映射

`CommonCommand` 使用 protobuf 字段 `cmd_type` 与 `param`，MQTT topic 为 `CommonCommand`，QoS 为 1，客户端限制发布频率不超过 10Hz。

| cmd_type | 行为 | param |
|---:|---|---|
| 1 | 兑换 17mm 弹丸 | 数量，必须为 10 的倍数 |
| 2 | 兑换 42mm 弹丸 | 购买数量 |
| 3 | 确认复活 | 0 |
| 4 | 金币立即复活 | 0 |
| 5 | 远程兑换弹量 | 购买数量 |
| 6 | 远程补血 | 0 |

空中支援使用独立 topic `AirSupportCommand`：`0` 结束、`1` 免费支援、`2` 付费支援，同样使用 QoS 1 与 10Hz 上限。

协议定位：PDF 第 53 页 `GlobalLogisticsStatus`、第 57 页 `RobotRespawnStatus`、第 59 页 `RobotDynamicStatus`、第 69 页 `CommonCommand`、第 73 页 `AirSupportCommand`、第 74 页 `AirSupportStatusSync`（文档页码分别为 52/56/58/68/72/73）。

## 5. 正式确认与 Mock 边界

- 正式模式发送后不预扣金币、不预加弹丸、不预改血量或复活状态。
- 交易只有在经济状态 revision 更新且金币、弹量、血量、复活或空中支援状态出现对应变化后才标记成功。
- 明确拒绝状态只在新的裁判状态 revision 中生效；5 秒没有结果则显示超时。
- `EconomyPanel -> Mock Requests` 默认开启。关闭该项且处于 `OfficialEvent` 时才允许走正式 MQTT 请求。
- 非官方场景始终使用确定性 Mock：发送后约 360ms 返回结果，并只修改一次本地状态；正式与 Mock 不会同时扣费。

交易状态统一为：`等待确认 / 等待裁判系统 / 操作成功 / 请求被拒绝 / 确认超时`。

## 6. 液态玻璃与动画边界

- 经济页是独占场景：打开或收拢动画期间，只保留图传背景与经济工作区；地图、模块列表、目标卡、底盘指示、遥测和战斗通知不得穿透到工作区下方。
- 根容器由顶部 POLAR 胶囊原位向下展开，打开 620ms、关闭 480ms，可从当前进度和速度反向；它不是居中的灰色弹窗，也不使用横向扫入。
- 根容器、选中分类和确认按钮使用强镜片：中心清晰，只有边缘折射与色散，`frost_amount = 0`。
- 商品、详情与状态区域使用独立 Regular 镜片，直接采样图传和经济轨道的 Combined Backdrop，不采样根镜片，也不依赖半透明深色矩形伪装玻璃。
- 文字、图标和命中区位于镜片层之上；交易状态在确认按钮和历史行内连续形变，不创建额外浮动面板。
- 工作区动画使用显示器刷新时间，不受摄像头或裁判数据帧率限制；背景仅在图传新帧到达时上传。
