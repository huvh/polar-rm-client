# 官方选手端对齐与链路验收计划

日期：2026-10-19。目标是以官方公开协议和界面说明补齐可验证的链路，同时保留 POLAR 自有功能。本文是实施计划；研究完成不代表功能已实现，离线通过不代表官方软件或实机互通。

## 1. 参考版本与现状

- [官方 2026 通信协议](https://bbs.robomaster.com/wiki/20204847/811363)：V2.0.0，2026-06-26。核验 PDF SHA-256：`8fdc484c58d503a3fb68f7c0515ae618b68eb2b058a8c876e1add5eeb8a7d81b`。自定义客户端接口共 **36 个 topic（11 上行、25 下行）**；研究矩阵明确整理了其中 **35 个 topic 的 171 条字段定义**。剩余 `RadarInfoToClient` 示例有歧义，不能把空字段清单解释为删除旧字段，也不能宣称已完整覆盖 36 个 schema。
- [官方赛事引擎/选手端资源](https://bbs.robomaster.com/wiki/20204847/804784)：研究时公开选手端为 **12.0.0.213_Student，2026-07-07**；界面依据 2026 年 7 月学生版手册，PDF SHA-256：`98e696e20023ad6e46926608e7c29b0b4cf49159de33ed21864006921801ff0d`。服务器发布日不能当作选手端版本；学生版权限不能代替正式比赛规则。
- [2027 协议页](https://bbs.robomaster.com/wiki/20204847/1969151)在本次研究时没有协议附件；[2027 规则](https://bbs.robomaster.com/wiki/20204847/1969149)与 2026 协议分开处理，不据此猜测 2027 字段或接口。
- 本地源码盘点以 `9e4fc8bf` 为起点，独立复核至 [full49 源码 db46402](https://github.com/lulunomaro/polar-rm-client/commit/db46402ae238a60db2df8623dc345781229d6c43)，相关协议/UI 路径未变。现有显式配置是 V1.3.1 与 V1.1.0 学生只读配置；V2 被明确拒绝。拒绝未知版本是现有安全边界，对齐 V2 需要新增完整版本能力，不能只改下拉框。

## 2. 实施顺序与完成条件

当前仅研究与 P0.1 的受限基础实现完成；P0.1 完整能力及后续步骤仍待完成。基础保持**未注册、不可选**，完成相邻层验证后才启用。

- [x] 官方协议、GUI、硬件说明与本地调用链盘点；独立复核新增字段、动作值、版本边界和未解决歧义。
- [x] **P0.1 受限基础：源码与离线验证完成。** 已加入版本包 `rm_client/backend/referee/rm2026_v2/`，声明 36 个 topic，支持 24 个下行 schema 和 11 个上行编码器；Radar 明确拒绝。新 24 方法与 full50 通过，详见[基础实现报告](referee_v2_codec_foundation_20261019.md)。编码能力不等于动作授权；配置仍未注册，未启用 V2。
- [ ] **P0.1 完整能力：解决 Radar 歧义并核对能力边界。** 在 `rm_client/backend/referee/` 现有版本所有者旁增加 V2 实现，复用 `wire.py`、`validation.py`；不修改 V1 全局字段/解码表。为 36 个 topic 列出实现或明确未支持的处置。重点验证 `GameStatus` 字段 9/10、`SentryStatusSync` 字段 3，以及类型、符号、重复字段、缺省与显式零/false。使用独立编码的字节样本，证明导入/调用 V2 不改变旧版本。Radar 歧义须取得可靠官方实现或样本，未解决前明确限制能力。
- [ ] **P0.2：投影与状态所有权。** 修改年度 `projection_policy.py`、`state_adapter.py`，按版本筛选 presence；在 `model.py` 与 `BackendManager._reset_state_for_scenario` 明确结果/结束原因的存储、重置和展示。保留哨兵强化状态，补齐需要呈现的空中支援状态。缺字段保留原值，显式零/false 正常更新；原始事件流不能成为第二个标量写入者。
- [ ] **P0.3：动作、规则与 UI 接通。** 在版本经济/动作策略及 `tactical_map.py`、`economy_mixin.py` 接入明确选项。V2 哨兵 `command_id` 仍是字段 1，10/11/12 是动作值，2 不再列出；现有 0–2 数字输入框不能直接沿用。空中支援命令值 3 是付费解除反制，`shooter_status` 仍是字段 5，其值 2 是状态。确认价格、资格、角色/阶段、取消和失败反馈后再显示动作，不猜费用或扩大整数范围代替规则。
- [ ] **P0.4：原始事件与界面消费者。** 审核 `combat_events.OfficialMatchFeed`、`ui/top_match_bar_controller.py`、`video_backend_mixin.py` 的 V1 专属门槛，只有语义已核对的 V2 路径才放行。保留学生只读隔离、接收时间与代际检查；结算结果不得沿用旧场次状态。
- [ ] **P0.5：最后注册并启用。** 扩展 `referee_profiles.py`、`backend/referee/registry.py`、`profile_change.py`、`mqtt_backend.py` 与资格检查。只有 codec、投影、动作和前端一致时才提供显式 V2 选择；不静默迁移旧配置/默认值。切换撤销旧证据，清理失败保持锁定并允许明确重试；不发明网络版本协商 topic。
- [ ] **P0.6：完整离线链路验收。** 每个支持的下行 topic 验证“字节→选定 codec→真实 adapter→状态→可见消费者”；每个启用动作验证“真实 UI→规则→编码→受保护发布→惰性接收端解码”。覆盖旧回调/已排空批次、过期接收时间、切换失败、未知 topic、畸形数据、显式零、限频、ESTOP 和只读模式。保留旧版本字节/行为与原断言，独立审查后再运行一次受控全量。

已交付的首个补丁仅覆盖 P0.1 的未注册基础及回归，没有改变默认版本、MQTT 生命周期、UI 动作范围、安全阈值或 native 端点。后续首先进行 P0.2 投影，再完成动作和消费者接入；注册仍是最后启用步骤。V2 与 V1 共享不少字段；不能要求所有 V2 数据包都被 V1 拒绝，也不能从相同 topic 名推断对端版本。

## 3. GUI 对齐：逐条确认已有覆盖，再补缺口

官方内置 GUI 不保证每项能力都有公开自定义接口。以下任务均需记录“已有覆盖 / 待实现 / 无公开接口 / 实机待验”，避免把按钮存在当作链路完成。

- [ ] **通用 HUD：** 阶段、时间、比分、己方经济、基地/前哨站、阵容、增益、热量/弹量/速度、底盘功率、模块健康、伤害/判罚/复活与事件反馈。所有展示有下行数据与缺失/过期/重置用例；不编造敌方私有数据。
- [ ] **角色流程：** 飞镖目标与发射闸门、能量机关、工程兑换、空中支援/反制、英雄部署、补给/复活、哨兵购买/姿态/结果。沿用现有 `hero_deploy.py`、战术地图、经济策略与确认界面，验证资格、费用、取消、重复操作和发送失败。
- [ ] **地图/总览：** 坐标单位、接收对象、攻防警示/字母标记、哨兵转发、路径与雷达/队友显示；区分 `MapClickCmd` 上行与 `MapClickInfo` 下行。界面关闭/失焦不能重放旧输入。
- [ ] **设置与操作员引导：** 显示配置版本、连接身份、输入来源、性能方案、官方侧配置要求及错误；明确本地/mock 状态。USB/信道等未开放设置保留官方操作指引，不虚构远程 setter。官方快捷键与现有 F12 安全语义冲突时保留安全约定。
- [ ] **结算：** 当前场次胜负/结束原因与非结算 255 值，资料不足的统计明确缺省；切换场景/配置后清除旧结算。
- [ ] **消息与扩展：** 保留现有 `[本地]` MatchChat 历史。官方 `0x0308` 是机器人向己方官方选手端发送的 UTF-16 通知，不能据此声明已有客户端间自由聊天 topic。联网聊天/语音若开发，须单列队伍扩展协议和接收端，不冒称官方接口。

继续保留 POLAR、DT7、自定义控制器、PRM1、自定义视效、旧图传与本地视觉等扩展；各自的接收端、权限和版本约定继续独立验证。

## 4. 官方软件与硬件验收清单

- [ ] **MQTT/裁判链路：** 使用明确版本的官方软件及配置，核对身份、订阅、下行状态和业务结果。发布成功只证明本地提交；`SentryCtrlResult` 没有唯一请求流水号，重复同命令不能凭 command_id 宣称逐次执行成功。
- [ ] **视频：** 相机→发射端→无线→接收端→官方选手端可见视频→UDP 桥→POLAR 解码/新鲜画面。官方 Shark 8 字节分片头与项目 Native `0x0310` 是不同路径。旧接收端型号/接口需实物确认，不能猜 USB 标识或端点；软件 H264 测试不等于旧硬件兼容。
- [ ] **键鼠与控制：** 官方端/自定义端输入来源互斥，核对物理接收端、机器人解析器、失焦/停止/退出/重连。硬件 A9 53 帧与 A5 裁判帧分开，现有资格检查和 ESTOP 不放宽。
- [ ] **自定义控制器/队伍协议：** 分别验证 A5 `0x0302`、`0x0309`、`0x0306`、MQTT `CustomControl`/`CustomByteBlock` 及队伍固件。容量限制不定义六关节浮点弧度含义；需核对板卡、固件、单位、串口路由与独立新鲜度。
- [ ] **文档歧义：** Radar 示例、`0x0303` 长度 12/15、`0x0307` 长度 103/105、QoS 示例与最高 1 的规范冲突，须确认、隔离或明确拒绝，不能用自制模拟器互相印证猜测。
