# Polar 终端连接旧图传的方法

记录日期：2026-10-21。适用于本次实际连接的旧图传及本地 Polar 源码。

## 1. 本次实际结果

- Polar HUD 已显示真实相机画面，用户现场确认有图传画面。
- 连续观察约 **174 秒**，实际解码分辨率 **1280×720**，平均约 **60 FPS**。
- 拔除视频输入后，HUD 清除旧画面并显示失联。
- 首版用户体感延迟约 0.5 秒，随后已减少旧图传解码、MJPEG 输出的帧线程缓冲。
  解码器启动到首帧的记录由约 395 ms 降到约 87 ms；这不是端到端延迟测量，
  最终体感延迟未再次定量验收。
- 按用户最终要求，断开后允许手动恢复或重启，不要求自动重连。
- 新图传仅提供“暂未实现”选项，没有实现其通信、取流或解码适配。

## 2. 接线与端口

```text
相机 / 旧图传发送端
  ├─ 独立供电
  ├─ UART 接 C 板 3-pin USART6（数据通信，不是电脑的视频输入）
  └─ 无线视频 → 旧图传接收端 → USB → 电脑
                                    ├─ COM14：接收端串口
                                    └─ RNDIS 网卡：视频数据

C 板 4-pin USART1 → 现有转换模块 / USB 串口线 → 电脑 COM13
```

| 接口 | 本次设备 / 参数 |
| --- | --- |
| 旧图传接收端串口 | **COM14**，DEVICE USB Virtual COM，VID:PID=`2CA3:001F` |
| 接收端虚拟网卡 | Remote NDIS based Internet Sharing Device |
| 电脑图传网卡 IPv4 | **192.168.42.105** |
| 子网掩码 | **255.255.255.0**（/24） |
| 接收端 IPv4 | **192.168.42.2** |
| 实测视频入口 | 接收端 → 电脑 **UDP 8080**，H.264 字节流 |
| COM13 | FTDI 串口线，控制器角度输入；不作为视频输入 |

COM8 不是本次图传接收端。COM14 和 COM13 不要混用。
图传收发端均需正常供电，USB 连接必须支持数据传输。

## 3. 启动顺序：先初始化接收端，再让 Polar 接收视频

当前方案由 **Polar 直接读取 UDP 8080 视频**；接收端的身份、通道和初始化仍依赖
官方客户端及串口后台。本次没有实现 Polar 自己的 COM14 初始化协议。

### 第一步：检查网卡

确认旧接收端已连接，电脑出现 RNDIS 网卡，其 IPv4 为
`192.168.42.105/255.255.255.0`。不要修改其他网卡。

`192.168.42.2` 能 ping 通只代表网络可达，不能单独证明视频正常。

### 第二步：让官方客户端先出图（这一步主要是检查接收端是否正确连接）

1. 进入目录：

   ```text
   D:\StandardRobot++\RoboMasterClient 11.0.1.128\RoboMasterClient 11.0.1.128
   ```

2. 通过该目录的 **start.bat** 启动，保持正确的工作目录，并启动配套后台。
3. 点击“进入客户端”，进入后按 **P** 打开设置。
4. 图传类型选择 **旧图传**。官方客户端重启后可能仍显示新图传，需要重新检查。
5. 选择与发送端匹配的身份、通道；本次成功配置为 **红 1 / R1-Hero、通道 1**。
   必要时点击“登录”触发配置。服务器登录状态与本地相机视频是否正常应分别判断。
6. **等到官方客户端确实显示相机画面**，再进行下一步。

### 第三步：释放官方显示窗口占用的视频端口

关闭官方客户端的**主显示窗口**（可用 Alt+F4），保留接收端的官方串口后台，
尤其是 `RMClientAssist_SerialPort`。

不要运行官方 `close.bat` 或把所有官方后台一起结束。UDP 8080 不能同时由官方
显示窗口和 Polar 独占；若 Polar 报 `WinError 10048`，先检查官方显示窗口是否仍在运行。

### 第四步：启动 Polar 并选择旧图传

1. 在 `D:\StandardRobot++\polar-rm-client` 双击 **启动.bat**，进入 HUD。
2. 按 **F8** 或右 Shift 打开配置界面。
3. 在“视觉”分类，右键打开 **图传画面**。
4. 将“来源”选择为 **旧图传**。
   英文或配置文件中的内部名称仍为 `Legacy VT02 UDP`，用于兼容已有配置。
5. 确认“图传画面”和“系统 → UDP 图传”模块已启用，关闭配置面板查看 HUD。
6. 如需下次自动保留，使用现有配置管理的保存功能，并保持启动加载配置开启。

旧图传固定监听 **0.0.0.0:8080**。现有 UDPVideo 的 `3334` 设置用于 Shark 等
转发入口，**无需把它改成 8080**；来源选择会采用旧图传自己的入口。

## 4. 新旧图传选项与手动恢复

- **旧图传**：使用本次已实际出图的接收实现。
- **新图传（暂未实现）**：停止旧图传取流、清除旧画面，HUD 明确显示
  “新图传：暂未实现”；不打开新设备、不启动新的通信或解码适配。
- 电脑摄像头、Shark UDP、UDP HEVC、原生 0x0310 等来源仍保留。代际选择也放在
  同一个“来源”设置内，避免同时选中相互矛盾的视频来源。

短暂停流后可尝试重新选择来源或重启 Polar。如果接收端下电、USB 重插后仍没有
视频，按第 3 节重新进行官方初始化，再关闭官方显示窗口、启动 Polar。
**接收端没有供电时，重启终端不会恢复画面。** 本次没有要求或宣称自动重连通过。

## 5. 当前依赖与实现说明

- 官方客户端：`RoboMasterClient 11.0.1.128`，负责当前方案的接收端初始化。
- 官方串口后台：实测关闭主窗口、保留后台后，Polar 仍能从接收端持续收流。
  尚未证明完全退出所有官方后台后也能保持该工作条件。
- FFmpeg：本机已将官方客户端随包的 FFmpeg 3.3.3 复制到：

  ```text
  D:\StandardRobot++\polar-rm-client\bin\ffmpeg.exe
  ```

  此文件作为本地运行资产，不提交到源码仓库。SHA-256：
  `c4b892aa6fb8ccb281abdcbf15a03d0747449d0c913a101ffca8e4251723cea5`。
  更换电脑时仍需准备符合项目运行要求的 FFmpeg。
- 当前实际 H.264 样本重复 SPS/PPS、持续使用非 IDR P 帧。已为旧图传单独增加
  参数集后的接入及 FFmpeg `showall` 策略；其他视频源保留原有恢复规则。
- 没有使用录屏、官方窗口截图、电脑摄像头或合成画面作为本次实时视频输入。
- 本次没有修改 C 板固件，没有授权角度转发、驾驶或电机动作。

接收端具体铭牌型号、当前收发端固件版本没有完成独立回读确认。

本记录以现场实际设备及成功视频为依据，不套用 VT03/VT13 的通信参数。
