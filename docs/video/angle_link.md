# 旧图传角度直发链路

适用于本机旧图传接收端 COM14（2CA3:001F）及已正常出图的 Polar。
开发与验证日期：2026-10-22。

## VT02 单编码器适配（2026-10-24）

用户确认发送端为 VT02。台架实测：发送端 UART 在 115200/8N1 输出 26 字节，
内容为 `02 03 + 六个 LE float32`，原 A5 帧头、源序号、CRC 和六字节保留区没有输出。
921600 下没有有效回程，不能继续套用 VT03/VT13 的串口配置。

本机单编码器请将 Angle Output 选为 **VT02 Encoder / VT02 单编码器直发**，
COM13、COM14 和原来的授权流程相同。此出口仅接受 J0 为 `[0, 2π)`、其余五轴为零。
它仍使用官方的 A5 和 DUML 09/63 外层；在空闲角度槽中加入源序号与 CRC16，
配套 C 板验证后恢复为 J0 加五个零。多轴输入会停止转发，不会静默丢弃其他轴。
普通 Legacy Receiver 和 Official Client Serial 的数据格式保持原样。

配套固件启用 `VIDEO_VT02_ENCODER=1`、`VIDEO_USART6_BAUDRATE=115200`。
直接将未经保护的 26 字节原始数据送入 C 板，只可用于诊断，不会触发电机控制。

本机旧固件还有封装差异：变动 A5 头时仅序号 0x13 的帧到达 UART；将内层头固定为
`A5 1E 00 13 02` 后连续接收恢复正常。VT02 专用出口采用该实测兼容头，源序号
仍在受 CRC16 保护的负载中递增并检查回绕、重复和超时。DUML 外层继续沿用官方固定
序号 0；修改外层序号的对照实验没有解决问题，已撤销该实验改动。
以上兼容规则来自本机实测，不把它当成所有 VT02 固件的统一协议。

2026-10-23 排查修正：官方日志的 COM14 对应 `VideoSerialPortThread`，当前
0x8A → 0x77 / 09/63 封装与该官方分支一致。`Video2025SerialPortThread` 使用
不同的主机地址 0xAA，不能仅因型号名称混用两个分支。

此前关闭 MQTTLink 后仍会在后台连接、重试，周期性的 MQTT 失联处理会撤销角度
授权。现在停用模块会真正停止连接和待重连任务；场景启动读取模块及 Auto Connect，
有意停用的 MQTT 不再触发“两秒失联”检测。启用 MQTT 时的断线锁定、全局急停、
配置切换、角度断流和图传掉线撤权保留。仅用本角度链时可保持 MQTTLink 关闭。

授权成功仅显示 toast 并记录 `controller_angle_arm`，避免成功弹窗抢焦点立即撤销 ARM。
“查看角度链路状态”和授权失败使用持久窗口，显示 COM13 连接、有效/拒收计数、
角度值、授权状态、真实/模拟转发数、COM14 就绪与完整写入数；每次查看同时在本地
`polar-field.jsonl` 留存 `controller_angle_status` 快照。窗口内容是点击时的快照。
2026-10-24 授权更新：独立编码器链路不再随窗口失焦撤权，切到 Keil 或查看状态
不会中断角度发送；键鼠控制仍在失焦时归零并锁定。
开启「启动自动授权角度 / Angle Auto Arm」并保存配置后，每次启动等待有效源数据、
RobotLink/Allow Drive 门禁及出口就绪，自动授权一次，再等下一帧新数据才发送。
急停、手动撤销或运行中断流后不自动重新 ARM；恢复后可手动授权，或重启终端。
当前 default 配置已开启该选项。新建配置默认关闭，避免改变其他机器人的配置行为。
2026-10-25 修复：配置加载会保留尚未枚举到的显式角度串口（例如 COM13），
不会因 USB 暂未接入或枚举尚未完成而将其替换并保存为 Stub。Auto 仍禁止用于角度入口。
配套编码器固件启用 `ENCODER_RADIO_AUTO_RESUME=1`：仅图传超时仍停机，但合法回程恢复后
重新对齐并使能；CAN 设备离线、电机故障、异常角度及 `encoder_run_enable=0` 继续锁定。

```text
编码器 CAN1/ID1 → 控制器 C 板 USART1 → 转换线 → COM13
  → Polar 校验 A5/0302 → 现有旧图传 COM14 线程 → 接收端
  → 无线链路 → 发送端 → USART6 → 接收 C 板 → CAN1/ID5 DM4310
```

本次新增 PC 端的 COM13 到现有 COM14 线程转发。没有修改或烧录两端 C 板，
电机映射继续由原先已通过官方客户端验证的接收固件负责。

## 操作

1. 重启 Polar 加载新代码，按 F8，在“系统 → 实体控制器角度”中设置：

   | 设置 | 值 |
   | --- | --- |
   | 角度接收串口 / Angle RX Port | COM13 |
   | 角度发送出口 / Angle Output | 本机选 VT02 单编码器直发 / VT02 Encoder；完整 A5 回程设备选 Legacy Receiver |
   | 角度转发串口 / Angle TX Port | Stub（直发模式不使用此项） |
   | 启用角度转发 / Forward Angles | 开 |
   | 角度模拟发送 / Angle Mock Writes | 先开，核对数据后关 |
   | 启动自动授权角度 / Angle Auto Arm | 开，保存后每次启动生效 |

2. 启用该模块；保留现有旧图传画面连接。COM14 由视频后端自动识别并独占，
   不要另外把它选成 Angle RX、RobotLink 或其他串口出口。
3. “RobotLink”需启用，“Allow Drive”需开启，“Port”使用 Stub（当前接线）。
   这些是沿用的转发授权门禁，不要求另一条机器人 USB 遥测链路。
4. 点“查看角度链路状态”，应有有效角度和持续递增的接收计数。
   模拟发送只增加 mock 计数，不会证明无线或车端已经收到。
5. 关闭模拟发送；自动授权开启时等待有效角度与出口就绪，无需输入 ARM。
   手动撤销、急停或运行中断流后，可点“授权角度转发”并输入 ARM 恢复。
   配置变更会停止旧连接；自动授权开启时，新配置就绪后自动授权一次。

旧的“官方选手端串口 / Official Client Serial”仍保留原来的独立 RX/TX 用法。
直发模式不需要官方客户端后台，也不会另外打开 COM14。

## 封装与线程

- COM13：115200/8N1，只接收长度为 30 字节、CRC8/CRC16 正确的 A5/0x0302 帧。
  沿用六个 little-endian float32、rad、既有工程档案范围；后六字节转发时清零。
  本次现场采到第一轴约 1.491 rad，其余五轴为零，45 帧有效、0 帧拒绝。
- COM14：沿用实际旧图传连接的 961200。自定义数据使用 DUML V1，
  sender=0x8A、receiver=0x77（type23/id3）、flags=0x40、cmd_set=9、cmd=0x63，
  内层是完整 39 字节 A5/0302，外层总长 52 字节。
  状态查询仍发往 0x0E，两个目的地址不可混用。
- 字节依据：本机官方 11.0.1.128 中 `CCSerialThread.SearchPackage`、
  `VideoSerialPortThread.OnVideoSendSerialProto/SendVideoProto` 的非冗余路径。
  外层 CRC 已用原官方 `CRCCheck_VideoSerialPort.cs` 独立计算对拍。
  本实现没有加载官方 DLL 或加入冗余优化器协议。
- 接收与授权逻辑放在 `controller_angles.py`；DUML 封装与单槽交接放在
  `legacy_angle_egress.py`；真实 COM14 写入只在 `LegacyReceiverControl` 原线程进行。
  状态查询、信道设置和角度不会多线程交错写串口。
- 角度发送不超过 30 Hz；既在采样转发处限频，也按 COM14 实际写完成时间限频。
  没有动作队列回放，不周期性重发旧角度。300 ms 角度超时、250 ms 授权心跳超时、
  急停、配置变更及换连接均撤权。单槽写入在执行前复核授权与新鲜度。
  取消角度请求不会关闭视频串口；串口写失败则停止该连接，需手动恢复。

## 验证边界

已完成 COM13 实读、官方封装字节对拍、真实 relay/接收端线程的假串口集成、
排队撤权/断流/断开/短写/限频测试及相关回归。没有向实体接收端发送角度，
尚未验证“Polar 直发 → USART6 到达 → ID5 电机跟随”。

最终相关回归运行 214 项：211 项通过，3 项因未提供本地视频样本、Npcap、
该测试环境的 PyAV 而跳过，0 失败、0 错误。静态质量门禁通过，0 初始化循环。
本地详细记录在 `user_data/field_evidence/angle-link-20261022/regression.json`、
`regression.log` 和 `quality.json`，不作为硬件输出成功证据。

`forwarded` 与 `angle_packets_written` 表示完整串口写完成，不表示车端消费。
现场验收应结合接收 C 板的 0x0302 计数、角度值和 ID5 反馈判断。
已开始的 OS 写不能撤回，接收 C 板现有的独立失联处理仍是必要条件。
